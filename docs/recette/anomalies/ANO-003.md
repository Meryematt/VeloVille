# ANO-003 - Une adresse d'API mal écrite affiche une trace Python dans le front

Cas de test : vérification complémentaire (REC-10, aucune trace Python)
Statut : ouverte
Sévérité : S3                 Priorité : P2
Constatée le 15/10/2026 par Meryem ATTARI

## Environnement

Version `55ac61c` (branche `main`, après correction de ANO-002), API
démarrée, front Streamlit, écran de connexion, compte `direction01`.
Constatée pendant le rejeu de ANO-002, après une erreur de saisie dans la
ligne `API_URL` du fichier `.env`.

## Reproduction

1. Lancer le front avec une adresse d'API mal écrite, sans modifier
   `.env` (PowerShell) :
   `$env:API_URL = "API_URL=http://127.0.0.1:8000"` puis
   `streamlit run front/app.py`.
2. Se connecter avec `direction01`.
3. Lire l'écran.

## Attendu / obtenu

Attendu : un message d'erreur en français, sans trace Python ni code
source à l'écran (même exigence que REC-10).

Obtenu : le front affiche l'erreur `requests.exceptions.InvalidSchema` et
la trace Python complète (fichiers et lignes de code). Le client HTTP du
front (`front/api_client.py`) ne transforme en message français que deux
erreurs réseau (API trop lente, API injoignable) ; les autres erreurs de
`requests`, comme une adresse invalide, remontent jusqu'à l'écran.
