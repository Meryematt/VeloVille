# ANO-002 - Chaque écran du front met environ 4 secondes à s'afficher

Cas de test : vérification complémentaire (exigence 7.1)   Statut : corrigée
Sévérité : S2                 Priorité : P1
Constatée le 15/10/2026 par Meryem ATTARI

## Environnement

Version `0646a95` (branche `main`, après correction de ANO-001), base
rechargée, compte `direction01`, front Streamlit (écrans Stations,
Incidents, Indicateurs), API démarrée avec `uvicorn api.main:app`.

## Reproduction

1. Démarrer l'API (`uvicorn api.main:app`) et le front
   (`streamlit run front/app.py`).
2. Se connecter avec `direction01`.
3. Changer un filtre ou passer d'un écran à l'autre, et mesurer le temps
   d'affichage.

## Attendu / obtenu

Attendu : toute consultation paginée répond en moins de 2 secondes sur le
jeu V1 (cahier des charges, exigence 7.1).

Obtenu : environ 4 secondes à chaque clic, sur tous les écrans. L'API
elle-même répond en quelques millisecondes : le temps est perdu dans la
connexion entre le front et l'API. Le front appelle l'API à l'adresse
`http://localhost:8000` ; sous Windows, Python essaie d'abord l'adresse
IPv6 de `localhost`, sur laquelle l'API n'écoute pas, et ne passe à
l'adresse IPv4 qu'au bout d'environ 2 secondes. Un écran fait deux appels
à l'API, d'où environ 4 secondes.

## Preuve

```bash
python -c "import time, requests; t = time.time(); requests.get('http://localhost:8000/sante'); print(round(time.time() - t, 2), 'secondes')"
python -c "import time, requests; t = time.time(); requests.get('http://127.0.0.1:8000/sante'); print(round(time.time() - t, 2), 'secondes')"
grep "^API_URL" .env
```

```text
2.05 secondes
0.0 secondes
API_URL=http://localhost:8000
```

## Correction

L'adresse de l'API utilise `127.0.0.1` au lieu de `localhost` : dans
`.env.example` et comme valeur par défaut dans `front/api_client.py`. Chaque
poste doit aussi mettre à jour la ligne `API_URL` de son fichier `.env`.
