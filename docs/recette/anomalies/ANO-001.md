# ANO-001 - Des lignes du journal d'import n'ont ni colonne ni valeur

Cas de test : REC-02          Statut : corrigée
Sévérité : S3                 Priorité : P1
Constatée le 15/10/2026 par Meryem ATTARI

## Environnement

Version `v0.9.0`, base rechargée (`sql/schema.sql`, `sql/comptes.sql`, puis
`python scripts/importer.py`), aucun compte utilisé (script d'import),
fichier concerné : `docs/journal-import.csv`.

## Reproduction

1. Recréer la base et charger les comptes, puis lancer
   `python scripts/importer.py`.
2. Ouvrir `docs/journal-import.csv`.
3. Compter les lignes qui contiennent une case vide :
   `grep -c ",," docs/journal-import.csv`.

## Attendu / obtenu

Attendu : chaque ligne du journal porte les six informations (fichier
source, identifiant, colonne, valeur, motif, décision).

Obtenu : 37 lignes sur 190 ont une case vide :

- les 12 lignes « doublon écarté » n'ont ni colonne ni valeur ;
- les 25 lignes « technicien absent » n'ont pas de valeur.

## Preuve

```bash
grep -c ",," docs/journal-import.csv
grep "doublon écarté" docs/journal-import.csv | head -1
grep "Technicien absent" docs/journal-import.csv | head -1
```

```text
37
trajets.csv,T480073,,,Ligne strictement identique à une ligne précédente,doublon écarté
incidents.csv,I2026-0011,technicien,,Technicien absent alors que l'incident est pris en charge (RG8),normalisation
```

Voir aussi le détail de REC-02 dans
[resultats-recette.md](../resultats-recette.md).

## Correction

Toute ligne du journal passe par la fonction `journal_line`
(`api/services/fiabilisation.py`), qui écrit « (vide) » à la place d'une
information vide. Les doublons portent la colonne d'identifiant et sa
valeur (`scripts/importer.py`).
